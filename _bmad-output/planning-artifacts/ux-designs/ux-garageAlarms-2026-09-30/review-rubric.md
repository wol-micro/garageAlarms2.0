# Ревью пары спайнов — garageAlarms 2.0

Проверено: `DESIGN.md`, `EXPERIENCE.md`, `.working/ux-dr.md` против `.memlog.md` (последние записи главнее), `SPEC.md`, `external-channels.md`, историй 4.1–4.7, 5.2–5.4, 6.1–6.7, 8.5, 8.8, 8.9, 9.1 из `epics.md` и `design-md-spec.md`. Дата: 2026-09-30.

## Общий вердикт

Визуальный язык и бот описаны плотно и в основном готовы к работе. `DESIGN.md` соблюдает порядок разделов и токены спецификации, пара «тёмный текст на красной плашке» проходит (5,05:1). Но последние решения memlog (18:46) в спайны не внесены. Ввод узлов, то есть добавление коллектора через веб и S3 через «Создать новую сеть»/«Присоединиться», описан по устаревшей модели. Получатели ежедневного отчёта, «Принято» из веба, период статистики и история 4.7 остаются в виде допущений или открытых вопросов, хотя по ним уже есть решения. Часть ключевых задач владельца (временное выключение критичного канала, первая подписка, редактор правил) не имеет сценария. Пока это не исправлено, архитектура и разработка историй 5.4, 4.6 и 6.1 будут опираться на неверное описание.

## 1. Покрытие сценариев — thin

Проверено: каждое решение memlog и каждая история из списка должны иметь поверхность в IA и сценарий (герой, нумерованные шаги, кульминация, путь отказа).

Есть: ночной дым (4.3–4.5), отпуск (8.9), новый датчик (5.4/6.2 — устарел), просмотр (4.7 — частично).

### Findings
- **critical** Сценарий добавления коллектора противоречит memlog («веб работающей системы → «Добавить коллектор» → Web Bluetooth → код → ключи автоматически») и истории 5.4. В спайне это отдельная страница, которую открывают после нажатия кнопки на H2, и точка входа из веба нигде не указана (EXPERIENCE: IA «Ввод узла», строка 2; §«Ввод узла» стр. 198; Flow 3, шаги 1–3; открытые вопросы, стр. 277–278). *Fix:* переписать Flow 3: веб узла → «Узлы» (или «Датчики») → «Добавить коллектор» → «нажмите кнопку ввода на коллекторе» + счётчик окна → `[Найти коллектор]` → код с наклейки → «Ключи сети переданы» → имя и зона → канал в «Новых каналах» в той же сессии. Добавить путь отказа: Web Bluetooth недоступен на самоподписанной странице → статическая страница с доверенного HTTPS + «Скопировать ключи» (5.4, AC 6). Закрыть вопросы 277–278.
- **critical** У ввода S3 нет выбора «Создать новую сеть» / «Присоединиться», а в вебе нет поверхности «Добавить большой узел», где выдаётся пакет ключей (memlog 18:46, 5.4, AC 3). Второй логический узел по спайну ввести нельзя (IA «Ввод узла», строка 1; §«Ввод узла» стр. 196; IA веба «Узлы»). *Fix:* первым шагом captive-страницы после кода — выбор из двух вариантов. В «Узлах» — действие «Добавить большой узел»: пакет ключей на время окна, кнопка «Скопировать», предупреждение «это секрет, не пересылайте». Добавить Flow 5 «Второй логический узел» с отказами: пакет устарел или неверен, неверный пароль WiFi.
- **high** Нет сценария для временного выключения тревог критичного канала (6.7) — главной аварийной задачи владельца: сломанный дымовик, ждём мастера. Нет и сценария первой подписки члена семьи (4.1). *Fix:* Flow 6: «Датчики» → канал → «Выключить тревоги» → срок (2 ч, ≤ 12 ч) → подтверждение → рассылка всем → обратный отсчёт → «включены снова». Flow 7: `/subscribe PIN` → приветствие + меню; отказы: неверный PIN, список заполнен.
- **high** Pushover во Flow 1 «пробивает беззвучный» у члена семьи. При этом Pushover задаётся одним ключом узла (4.4 «As a владелец», «Доступы» — одно поле), и поверхности для ключей членов семьи нет (Flow 1, шаг 2). *Fix:* либо героем Flow 1 сделать владельца, либо зафиксировать в «Доступах» «ключ пользователя или группы Pushover» и описать, что семья подключается через группу.
- **medium** Нет сценариев для редактора правил с `when` (8.8/8.5), назначения оператора (8.9, AC 5 — Flow 2 предполагает, что роль уже выдана), OTA узла с откатом (5.2) и смены секрета в «Доступах». *Fix:* добавить короткие сценарии хотя бы для 8.8 (ошибка `when` с позицией) и 5.2 (откат).
- **low** У Flow 4 нет пути отказа (не помещается в одно сообщение, ведущего нет — бот молчит). *Fix:* добавить.

### Findings
- **high** `button-danger` (текст `critical` на прозрачном фоне) внутри «Окна подтверждения», у которого фон `{colors.raised}`, даёт 4,14:1 — меньше, чем обещает Accessibility Floor (≥ 4,5:1 на всех парах) (DESIGN, компоненты `button-danger`, §Components «Окно подтверждения»; EXPERIENCE, стр. 204). *Fix:* в окне подтверждения кнопка опасного действия залита `{colors.critical}` с текстом `{colors.on-critical}` (5,05:1). Контурный вариант — только на `bg`/`surface`. Добавить в `DESIGN.md` таблицу контраста важных пар.
- **medium** Смешанные значения в компонентах не разрешаются в токены: `(critical 55% + white)`, `12% поверх`, `linear-gradient(... 16% ...)`. Контраст текста на них нигде не указан, и на тинте `warn-banner` `text-2` не проходит. *Fix:* вынести hex-токены `fault-tint: #26273e`, `warn-tint: #2d2e24`, `accent-tint: #143844`, `critical-edge: #ff849c`. Текст на `warn-tint` — только `{colors.text}`.
- **medium** Граница поля `input` (`{colors.border}`) имеет контраст 1,4–1,5:1 к фону — поле плохо различимо (1.4.11). *Fix:* отдельный токен `input-border` с контрастом не ниже 3:1 к `surface` (например, около `#4a6078` — проверить).
- **low** `typography.input-mobile/small/label/alarm` без `fontFamily`: наследование подразумевается, но не записано. *Fix:* одной строкой в §Typography написать «без fontFamily — наследует body».
- **low** Кольцо `focus` на красной плашке — 2,61:1. После удаления `alarm-banner-button` (см. §7) вопрос снимается. *Fix:* если кнопка останется, давать кольцо со смещением на тёмной подложке.

## 4. Покрытие состояний — thin

### Findings
- **medium** Нет пустых состояний веба: нет подписчиков, правил, зон, событий, «Новых каналов». Нет состояний первой загрузки (медленный ESP), истёкшей сессии, неверного логина или блокировки после серии попыток, ошибки сохранения при потере узла посреди правки. Нет состояния «репликация зависла» (узел пропал, и «На всех узлах» не наступает никогда). *Fix:* добавить строки в State Patterns, например «Сохранено на этом узле; узел-коридор не на связи — применится при возврате».
- **medium** Ввод: не описаны выключенный Bluetooth, отказ в разрешении, «коллектор не найден», captive-страница, которая не открылась сама (нужен запасной адрес), неверный пароль WiFi на S3. *Fix:* добавить в State Patterns и в пути отказа Flow 3 и Flow 5.
- **medium** Плашка тревоги с `role="alert"` при опросе раз в 5–10 с (EXPERIENCE, стр. 152–153) будет перерисовываться, и экранный чтец начнёт повторять тревогу — «флуд» в доступности. *Fix:* вставлять узел плашки один раз при появлении события, обновлять только текст контекста в `aria-live="polite"`, не пересоздавать `role="alert"`.
- **medium** Предупреждение браузера о самоподписанном сертификате появляется до страницы входа, поэтому «страница входа это объясняет» (стр. 183) и UX-DR27 невыполнимы как записано. *Fix:* объяснение и отпечаток сертификата — на финальном экране ввода S3 («Браузер предупредит… отпечаток: …»). Страница входа только напоминает о нём.
