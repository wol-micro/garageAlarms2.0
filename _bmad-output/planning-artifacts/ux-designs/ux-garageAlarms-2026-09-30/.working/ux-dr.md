# UX Design Requirements — garageAlarms 2.0

Источник: `../EXPERIENCE.md`, `../DESIGN.md`. Формат: UX-DR → истории epics.md: требование. ID стабильны; новые — только в конце; снятые помечены «(снято)». переносится как есть.

## Telegram-бот

- UX-DR1 → 4.1: неподписанный чат на любую команду, кроме `/subscribe`, получает только «Чтобы получать тревоги: /subscribe PIN»; верный PIN — «Вы подписаны. Тревоги придут сюда.» и меню подписчика; неверный — «Неверный PIN.»; лимит — «Список подписчиков заполнен — обратитесь к владельцу.»
- UX-DR2 → 4.2, 4.7: `/menu` и `/start` присылают главное меню; кнопки по роли (подписчик: Датчики, События, Статус, Отчёт, Тест, 🔕 Моя тишина, Отписаться; оператор: + Режим; владелец: + 🔇 Общая тишина, Ведущий, Перезагрузка, Статистика, без Отписаться).
- UX-DR3 → 4.2: нажатие кнопки меню правит то же сообщение (`editMessage` с `parse_mode=HTML`) и вызывает `answerCallbackQuery`; новое сообщение меню — только по `/menu`; каждый экран кончается `‹ Меню`.
- UX-DR4 → 4.2, 8.9: роль проверяется при нажатии по `from.id`; кнопка чужой роли отвечает «Эта команда доступна владельцу.» / «Смена режима доступна владельцу и операторам.» и ничего не исполняет.
- UX-DR5 → 4.2: первая строка главного меню — `🟢 Всё спокойно · режим «…»` или `🚨 Активна тревога: <тип> · <зона>`, плюс `🔇 общая тишина до ЧЧ:ММ` и (только своему чату) `🔕 моя тишина до ЧЧ:ММ`.
- UX-DR6 → 4.7, 7.1: «Датчики» — по зонам; если не помещается в одно сообщение, сначала зоны кнопками; строка канала `<точка> <тип> <имя> — <состояние>`; binary — `· последний раз <дата время>` (или «ни разу»); numeric — `<значение с единицей> · сутки <мин>…<макс>` (сутки — 7.1) с десятичной запятой; numeric у порога — 🟡 рядом со значком типа.
- UX-DR7 → 4.7, 7.9: неисправный канал в «Датчиках» — 🟣 со словом (`обрыв`/`КЗ`/`неисправен` с ЧЧ:ММ), молчащий — ⚪ `молчит N мин`.
- UX-DR8 → 4.7: «События» — блок «Сейчас» (активные: «не подтверждено» / «принято: кем») и история с листанием `‹ Раньше` / `Позже ›` в том же сообщении, по N событий (значение — `tunables.md`, старт 10).
- UX-DR9 → 4.2: «Статус» и `/status` — ведущий, узлы на связи с uplink, пропавшие «пропал N мин назад», режим, общая тишина, неисправные каналы.
- UX-DR10 → 4.7: «Статистика» — только владельцу, за 7 дней: подписчики с ролями, перезагрузки по узлам с причинами, отказы (пропадания узлов, ошибки доставки, неисправности каналов).
- UX-DR11 → 4.2, 8.9: `/leader`, `/reboot`, `/mode`, отписка — экран выбора → экран последствия с `[✅ Подтвердить] [✖ Отмена]`; подтверждение устаревает (срок — `tunables.md`, старт 2 мин) с ответом «Время подтверждения вышло, повторите.» и не исполняется.
- UX-DR12 → 4.2, 6.7: попытка изменить правило, конфиг или выключить тревоги канала из Telegram получает «Правила меняются только в локальном вебе.»
- UX-DR13 → 4.3: каждое сообщение бота кончается строкой `🏠 <имя узла> · <статус по-русски>` (например `🏠 гараж · ведущий`; ведущий/ведомый/уступил/изолирован).
- UX-DR14 → 4.3: сообщение, пролежавшее в очереди дольше порога, второй строкой несёт `⏳ с опозданием · событие в ЧЧ:ММ`.
- UX-DR15 → 4.3: первая строка события — один значок важности (🚨 ⚠️ 🔧 ✅ ℹ️) и значок типа (🔥 💧 🌡 🚶 🔌 📟); ЗАГЛАВНЫЕ — только в заголовке критичной тревоги.
- UX-DR16 → 4.3, 4.5: критичная тревога — новое сообщение: `🚨 <тип> <b>ТИП · ЗОНА</b>`, «Сработал в ЧЧ:ММ.», тренд зоны за окно правила скорости изменения (по умолчанию 10 мин; строки нет без числового канала), `Соседние зоны: <точка> <зона> — <худшее состояние>` через « · » по графу зон (строки нет без соседей), «Не подтверждено.», кнопки `[✅ Принято] [📋 Статус]`.
- UX-DR17 → 4.5: «Принято» из Telegram или Pushover правит сообщение тревоги у всех получателей: кнопки убраны, строка статуса — `✅ Принято: <кто>, ЧЧ:ММ. Повторы остановлены.`; повторы и Pushover прекращаются.
- UX-DR18 → 4.5: длящийся неподтверждённый дым каждые 15 мин даёт новое `🔁 🔥 ДЫМ всё ещё · <ЗОНА> — N мин с начала, не подтверждено` с трендом и теми же кнопками; окончание — `✅ 🔥 Дым в <зоне> прекратился · ЧЧ:ММ`.
- UX-DR19 → 4.5: «🔕 Моя тишина» — `[1 ч] [4 ч] [8 ч] [Выключить]`; до срока некритичное этому чату — без звука, критичное — со звуком; снимается само; экран говорит «Критичные тревоги всё равно зазвонят.»
- UX-DR20 → 4.5: «🔇 Общая тишина» и `/mute N` — только владельцу, не больше `MAX_MUTE_HOURS`; ответ «Некритичное не отправляется до ЧЧ:ММ. Тревоги придут.»
- UX-DR21 → 4.4: Pushover для критичного — на ключ группы; заголовок = первая строка тревоги без HTML, текст = время, зона, тренд; некритичное в Pushover не уходит.
- UX-DR22 → 4.6: уведомление о перезагрузке — только владельцу: узел, причина по-русски (код в скобках), время возврата; не чаще 1 за 15 мин (неожиданная) / 1 за 6 ч (плановая).
- UX-DR23 → 4.6: ежедневный отчёт в 09:00 — всем подписчикам, начинается с `📊`: узлы на связи/пропавшие, ведущий, события за сутки; тот же отчёт по кнопке «Отчёт».
- UX-DR24 → 8.9: смена режима рассылается всем как `🛡 Режим «<режим>» включён — <кто>, ЧЧ:ММ`; экран подтверждения говорит, что критичные тревоги режим не меняет.
- UX-DR25 → 3.9: закреплённая аренда в чате владельца первой строкой читается человеком (`📌 Связь держит «<узел>» · до ЧЧ:ММ. Служебное, не откреплять.`), машинная часть — второй строкой в `<code>` (формат — 3.9); продление правит сообщение без звука.
- UX-DR26 → 4.2: родной список `/`-команд соответствует роли чата [ASSUMPTION: scope по чату] и перерегистрируется при смене версии меню.

## Служебный веб

- UX-DR27 → 6.1, 5.4: веб — только HTTPS в локальной сети; без входа доступна только страница входа («Неверный логин или пароль.» при ошибке); объяснение предупреждения о сертификате и отпечаток — на финальном экране ввода S3 и в инструкции к корневому сертификату, страница входа только ссылается на них.
- UX-DR28 → 6.1: тема Cold Steel NOC; текст на `{colors.critical}` — `{colors.on-critical}`; пары текст/фон ≥ 4,5:1, границы полей и фокус ≥ 3:1 — по таблице контраста DESIGN.md §Colors; кнопка опасного действия залита `critical` с текстом `on-critical`.
- UX-DR29 → 6.1: главная — сводная полоса (узлы N/M, ведущий, uplink, режим, тишина, MQTT, конфликты), активные тревоги, неисправности, последние события, меню разделов; в заголовке — имя узла.
- UX-DR30 → 6.1, 4.5: активная тревога — `alarm-banner` над любой страницей, без кнопок: «не подтверждено» или «✅ Принято: <кто>, ЧЧ:ММ» и подсказка «Подтвердить можно в Telegram или Pushover»; `role="alert"` вставляется один раз, обновления контекста — `aria-live="polite"`; при `prefers-reduced-motion` — статичная рамка без свечения.
- UX-DR31 → 6.1: при ширине < 560px меню — ряд вкладок, формы в одну колонку, таблицы — карточки, поля 16px, все цели касания ≥ 44px, без горизонтальной прокрутки.
- UX-DR32 → 6.1, 6.4: «Узлы» — роль по-русски, uplink, RSSI, полоса uplink за 24 ч с числом разрывов словами, версия, адрес веба; пропавший — fault и «пропал N мин назад».
- UX-DR33 → 6.4: в «Узлах» задаются `leader_priority` и ручной ведущий «узел до ЧЧ:ММ»; действующий выбор виден в сводной полосе со сроком.
- UX-DR34 → 6.6: «Забыть узел» — окно подтверждения с залитой `button-danger`, называющее узел и последствие («события о его пропаже прекратятся, сам он не вернётся»).
- UX-DR35 → 6.2, 7.2: «Датчики» — сверху «Новые каналы» со счётчиком в меню; канал «без имени» показывает тип драйвера и адрес (ROM ID / I²C) и форму: имя, зона, назначение, критичность.
- UX-DR36 → 6.2: форма канала — явное «Сохранить»; значение вне диапазона `ga_config.h` — у поля цветом warn со значком ⚠ и текстом «Значение X вне диапазона A…B <единица>.»; статус «Сохранено на этом узле» → «На всех узлах».
- UX-DR37 → 6.7: у критичного канала «Выключить тревоги» — выбор срока (по умолчанию 2 ч, максимум 12 ч, «до ЧЧ:ММ»), окно подтверждения; выключенный канал — `warn-banner` «до ЧЧ:ММ, кем» с отсчётом; бессрочного варианта нет.
- UX-DR38 → 6.3: «Зоны» — добавить/удалить зону и соседство списком пар, без перетаскивания; удаление зоны предупреждает, что её каналы станут «без зоны».
- UX-DR39 → 8.8: «Правила» по наборам; форма создания — параметры шаблона, `when`, набор, важность, адресаты.
- UX-DR40 → 8.5, 8.8: `when` — моноширинное поле со счётчиком `n/256`; ошибка при сохранении подчёркивает позицию цветом warn и называет её («позиция 34: ожидалось `)`»); длиннее 256 или глубже 8 — «Слишком длинное условие» / «Слишком глубокая вложенность: больше 8 уровней.»
- UX-DR41 → 8.8, 6.7: выключение базового правила критичного канала в «Правилах» ведёт в тот же выбор срока, что UX-DR37.
- UX-DR42 → 8.6, 8.8: режимы показаны со своими наборами и текущим режимом; правило незнакомого шаблона — «не исполняется на узле X».
- UX-DR43 → 6.4, 8.9: «Подписчики» — список с ролями, переключатель роли оператора, удаление (у владельца недоступно), смена PIN.
- UX-DR44 → 4.4, 9.1, 6.1: «Доступы» — токен Telegram, `OWNER_CHAT_ID`, ключ группы Pushover (вся семья), MQTT-логин/пароль, логин и пароль веба — только для этого узла; поля только на запись, «задан · изменён ДД мес», пометка «хранится только на этом узле».
- UX-DR45 → 9.1: «MQTT» — адрес, порт, TLS, префикс, «включено» как общий конфиг; состояние подключения и время последней связи.
- UX-DR46 → 9.3: при недоступном брокере «MQTT» показывает заполнение буфера и «Telegram и Pushover работают как обычно».
- UX-DR47 → 5.2: «Обновления» принимают образ этого узла и показывают этапы (проверка подписи → перезагрузка → вход в сеть → готово / откат); неподписанный — «Образ отклонён: подпись не подтверждена.»
- UX-DR48 → 5.2: пока обновляется другой узел, загрузка недоступна: «Ждёт: обновляется <узел>».
- UX-DR49 → 6.5: «Конфликты» — две карточки значений с узлом и временем, «Оставить это»; число открытых — в меню и сводной полосе.
- UX-DR50 → 6.6: экспорт — файл мягкого конфига без секретов; импорт показывает отличия «было → станет» с итогом «изменится N» и применяется после окна подтверждения.
- UX-DR51 → 6.1: весь веб с клавиатуры, видимое кольцо `{colors.focus}`; состояние дублировано словом; ошибки полей через `aria-describedby`; `lang="ru"`.

## Ввод узла

- UX-DR52 → 5.4: ввод S3 — captive-страница его WiFi-точки в любом браузере: код с наклейки → «Создать новую сеть» или «Присоединиться» (вставить пакет ключей) → WiFi → токен Telegram, `OWNER_CHAT_ID`, ключ группы Pushover → логин/пароль веба → необязательно MQTT-логин, имя, зона → финал с адресом веба и отпечатком сертификата.
- UX-DR53 → 5.4: «Добавить коллектор» в «Узлах» веба работающей системы: кнопка ввода + счётчик → `[Найти коллектор]` (Web Bluetooth, Chrome Android / Bluefy iPhone) → сверка EUI → код с наклейки → ключи сети передаются автоматически → каналы «без имени»; в Safari — «Откройте эту страницу в Bluefy.»
- UX-DR54 → 5.4: все страницы ввода и мастера — одна колонка ≤ 480px, «Шаг N из M», одно действие на экран, видимый счётчик окна; тексты: «Окно ввода закрыто. Нажмите кнопку ввода на узле.» / «Код не подошёл, проверьте наклейку.»
- UX-DR55 → 5.4: страницы ввода содержат только секреты и активацию; финальный экран говорит, что узел перезагружается, и (для S3) адрес его веба.
- UX-DR56 → 5.4, 6.2: каналы нового коллектора видны в «Новых каналах» в той же сессии, проверочное срабатывание приходит в Telegram с заданным именем и зоной.
- UX-DR57 → 5.4, 6.4: «Добавить большой узел» в «Узлах»: код с наклейки нового узла → «Скопировать ключи» копирует пакет, зашифрованный этим кодом; пакет не показывается; подпись «Это секрет. Вставляйте только на страницу ввода узла.»; неподходящий пакет на S3 — «Пакет ключей не подошёл. Скопируйте его заново в вебе работающего узла.»
- UX-DR58 → 5.4: если Web Bluetooth недоступен на странице с сертификатом узла — «Bluetooth недоступен на этой странице», «Скопировать ключи» и статическая страница ввода с доверенного HTTPS со вставкой пакета.
- UX-DR59 → 6.1: «Доступы» → «Сертификат»: скачивание корневого сертификата своего CA узлов, объяснение предупреждения браузера и пошаговая установка для iPhone и Android.
- UX-DR60 → 5.4: отказы ввода: Bluetooth выключен / нет разрешения, коллектор не найден (с «Искать снова»), captive-страница не открылась (адрес на наклейке), неверный пароль WiFi (остаётся на шаге) — тексты из State Patterns.

## Добавлено при ревью

- UX-DR61 → 5.3: «Обновления» показывают таблицу коллекторов: версия, «в очереди» / «передаётся N%» / «готово» / «откат»; очередь по одному.
- UX-DR62 → 6.1: запрос не из локальной сети отклоняется без страниц.
- UX-DR63 → 3.1, 6.1: у каждого секрета в «Доступах» — «задан на узлах: …» по флагам heartbeat.
- UX-DR64 → 6.7: выключение и включение тревог канала рассылается всем: `⚠️ <тип> Тревоги канала «<имя>» выключены до ЧЧ:ММ — <кто>` / `✅ <тип> Тревоги канала «<имя>» включены снова`; в «Датчиках» бота канал помечен «тревоги выключены до ЧЧ:ММ».
- UX-DR65 → 6.1–6.4, 8.8: пустые состояния разделов — одна строка и действие (тексты в State Patterns); первая загрузка — каркас со значениями «…».
- UX-DR66 → 3.10, 6.2: статус репликации при пропавшем узле — «Сохранено на этом узле; «<узел>» не на связи — применится при возврате»; узел не ответил при сохранении — «Не сохранено: узел не отвечает. Откройте другой узел.»
- UX-DR67 → 6.1: истёкшая сессия ведёт на вход с «Сессия истекла, войдите снова»; перед уходом с несохранённой формы — предупреждение.
- UX-DR68 → 6.1: после 5 неверных попыток входа — пауза 5 мин с текстом «Слишком много попыток. Повторите через 5 мин.», запись в журнал.
- UX-DR69 → 5.4, 6.4: пакет ключей одноразовый, действует 30 мин; просроченный или использованный отклоняется с текстом-подсказкой.
