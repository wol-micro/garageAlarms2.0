# garageAlarms 2.0 — Experience Spine

> Макеты: [тревога в боте](mockups/screen-bot-alarm.html) · [меню бота и «Датчики»](mockups/screen-bot-menu.html) · [сводка веба](mockups/screen-web-summary.html) · [добавление коллектора](mockups/screen-web-add-collector.html). При расхождении с макетом прав этот документ.

## Foundation

Три поверхности, одна система:

1. **Telegram-бот** — основной интерфейс семьи: тревоги, подтверждение, просмотр, смена режима. Отправляет и читает команды только `LEADER`; любое сообщение бота подписано узлом.
2. **Служебный веб** — на каждом логическом узле, только локальная сеть, HTTPS, вход по логину и паролю узла. Только владелец. Назначение — настройка, не наблюдение. Сертификаты узлов выпускает свой CA системы; корневой сертификат ставится на телефон один раз из «Доступов»; до установки браузер предупреждает о сертификате.
3. **Страницы ввода узла** — логический узел S3 через свою WiFi-точку (страница в любом браузере); коллектор H2 — из веба работающей системы, «Добавить коллектор» по Web Bluetooth (Chrome на Android, Bluefy на iPhone). Только секреты и активация.

Люди: **владелец** (всё), **оператор** (член семьи с правом `/mode`, назначается в вебе), **подписчик** (член семьи). Семья — не новички, но интерфейс без усложнений.

Слова для пользователя: `LEADER` — «ведущий», `FOLLOWER` — «ведомый», `YIELDED` — «уступил», `ISOLATED` — «изолирован». «Окно подтверждения» (веб) и «экран подтверждения» (бот) — один паттерн.

Инварианты, которые UX не нарушает ни на одной поверхности: тишина не глушит критичное; правила меняются только в вебе; критичное выключается только временно (2 ч по умолчанию, максимум 12 ч) с оповещением всех; внешние секреты не уходят в сеть.

Визуальный язык — `DESIGN.md`; здесь — поведение. Все тексты для пользователя — русский. Сроки и лимиты — `tunables.md`; помеченные [ASSUMPTION] стартовые значения переносятся туда.

## Voice and Tone

Коротко, по делу, без канцелярита и восклицательных знаков. Сначала что и где, потом когда, потом что делать.

| Делать | Не делать |
|---|---|
| «🚨 🔥 ДЫМ · ГАРАЖ» | «Внимание! Обнаружено срабатывание датчика №17» |
| «🟢 🔥 Дым — норма · последний раз 12 сен 14:03» | «binary ch3 state=0» |
| «Узел «коридор» пропал 12 мин назад» | «Node 0x7C… stale» |
| «✅ Принято: член семьи, 03:14. Повторы остановлены.» | «ACK received» |
| «Включить режим «Уехал»? Критичные тревоги это не меняет.» | «Вы уверены?» |
| «Неверный PIN.» | «Ошибка авторизации 403» |
| «Правила меняются только в локальном вебе.» | Молча игнорировать команду |
| «Значение 90 вне диапазона 1…60 с.» | «Invalid value» |
| Роли узла по-русски: ведущий, ведомый, уступил, изолирован | `LEADER`, `FOLLOWER` в пользовательском тексте |

Причины сброса — по-человечески («провал питания», «сторожевой таймер», «перезагрузка по команде»), код — в скобках для владельца. Режимы «Дома», «Уехал», «Ночь» — примеры из `rule-templates.md`; список задаёт владелец.

Канонические тексты отказов ввода: «Окно ввода закрыто. Нажмите кнопку ввода на узле.» · «Код не подошёл, проверьте наклейку.»

## Telegram-бот: сообщения и клавиатуры

**Меню редактирует себя.** Нажатие кнопки меняет то же сообщение (`editMessage`, `parse_mode=HTML`); новое сообщение меню — только по `/menu`. Каждый экран кончается `‹ Меню`. На каждое нажатие — `answerCallbackQuery`.

**События — новыми сообщениями.** Тревога, напоминание, смена режима, выключение тревог канала, отчёт, перезагрузка — всегда новое сообщение: правка не звенит.

**Роль проверяется при нажатии** по `from.id`. Кнопка роли, которой у чата нет: «Эта команда доступна владельцу.» / «Смена режима доступна владельцу и операторам.»

**Опасные команды** (`/mode`, `/leader`, `/reboot`, отписка) — экран выбора → «Что произойдёт» с `[✅ Подтвердить] [✖ Отмена]`. Подтверждение устаревает [ASSUMPTION: 2 мин]; устаревшая кнопка → «Время подтверждения вышло, повторите.» Повторная доставка того же `update_id` не исполняется.

**Экраны:**

- **Главное меню** — строка состояния: `🟢 Всё спокойно · режим «Дома»` или `🚨 Активна тревога: дым · гараж`; плюс `🔇 общая тишина до ЧЧ:ММ` и (только в своём меню) `🔕 моя тишина до ЧЧ:ММ`. Ниже кнопки по роли.
- **📡 Датчики** — по зонам (`<b>Гараж</b>`), строка канала по `DESIGN.md`: контакт `🟢 🔥 Дым — норма · последний раз 12 сен 14:03` (или «ни разу»); числовой `🟢 🌡 Температура — 23,4 °C · сутки 18,1…26,0`; у порога — `🟡`; неисправный `🟣 💧 Протечка — обрыв с 02:40`; молчащий `⚪ … — молчит 12 мин`. Не помещается в одно сообщение — сначала зоны кнопками, затем зона.
- **📜 События** — «Сейчас» (активные: «не подтверждено» / «принято: кем»), ниже история: время, значок, правило, зона, чем кончилось. Листание `‹ Раньше` / `Позже ›` [ASSUMPTION: 10 событий на страницу].
- **🩺 Статус** — ведущий; узлы на связи с uplink; пропавшие «пропал N мин назад»; режим; общая тишина; неисправные каналы.
- **📈 Статистика** (владелец) — за 7 дней: подписчики с ролями; перезагрузки по узлам с причинами; отказы — пропадания узлов, ошибки доставки, неисправности каналов.
- **🔕 Моя тишина** — `[1 ч] [4 ч] [8 ч] [Выключить]`. Некритичное этому чату — без звука до срока; снимается само. Текст экрана: «Критичные тревоги всё равно зазвонят.»
- **🔇 Общая тишина** (владелец) — сроки до `MAX_MUTE_HOURS`, некритичное не отправляется никому. Ответ: «Некритичное не отправляется до ЧЧ:ММ. Тревоги придут.»
- **🛡 Режим** — кнопки режимов, текущий отмечен; → подтверждение с перечнем, что включится/выключится.

**Тревога и её жизнь:**

1. Критичное событие → новое сообщение по анатомии `DESIGN.md`: заголовок; время; тренд зоны `🌡 гараж: 24,0 → 31,5 °C за 10 мин ↑` (за окно правила скорости изменения, по умолчанию 10 мин; строки нет, если в зоне нет числового канала); `Соседние зоны: <точка> <зона> — <худшее состояние>` через « · » по графу зон (строки нет, если соседей нет); «Не подтверждено.»; кнопки `[✅ Принято] [📋 Статус]`. Одновременно — Pushover `priority=2` на ключ группы.
2. «Принято» (здесь или в Pushover) → сообщение правится у всех получателей (`tg_msg_id` хранится по каждой единице доставки): кнопки убираются, строка статуса становится `✅ Принято: <кто>, ЧЧ:ММ. Повторы остановлены.` Повторы и Pushover гаснут везде.
3. Дым держится без «Принято» → каждые 15 мин новое `🔁 🔥 <b>ДЫМ всё ещё · ГАРАЖ</b> — N мин с начала, не подтверждено` с трендом и теми же кнопками.
4. Дым кончился → `✅ 🔥 Дым в гараже прекратился · 03:41`.

**Прочие события:** `⚠️` некритичный порог; `🔧` неисправность (для критичного канала — критична, с кнопками тревоги); `🛡 Режим «Уехал» включён — <кто>, 18:40` всем; `⚠️ 🔥 Тревоги канала «Дым · гараж» выключены до 05:12 — владелец` всем и `✅ 🔥 Тревоги канала «Дым · гараж» включены снова` всем; `📊` ежедневный отчёт в 09:00 **всем подписчикам** — узлы на связи/пропавшие, ведущий, события за сутки.

**Служебное владельцу:** `🔄 Узел «коридор» перезагрузился: провал питания (BROWNOUT). На связи с 03:40.` (≤ 1 за 15 мин неожиданных, ≤ 1 за 6 ч плановых).

**Pushover** (только критичное, ключ группы — будит всех членов группы с приложением): заголовок = первая строка тревоги без HTML, текст = время + зона + тренд; подтверждение в Pushover = «Принято».

## Аренда лидера в чате

Закреплённое сообщение в чате владельца видно в шапке всегда, поэтому первая строка — для человека:

`📌 Связь держит «гараж» · до 03:27. Служебное, не откреплять.`

Вторая строка — машинная аренда в `<code>` (формат — архитектура 3.9). Продление правит то же сообщение без звука и без нового закрепа.

## Component Patterns

| Компонент | Где | Поведение |
|---|---|---|
| Inline-меню | бот | правит себя; `‹ Меню` внизу; роль проверяется при нажатии |
| Экран / окно подтверждения | бот, веб | «что произойдёт» + Подтвердить/Отмена; в боте устаревает; идемпотентно; в вебе кнопка называет действие |
| Сообщение тревоги | бот | новое сообщение; после «Принято» правится у всех |
| Подпись узла | бот | последняя строка каждого сообщения `🏠 <имя узла> · <статус>`, например `🏠 гараж · ведущий` |
| Пометка «с опозданием» | бот | вторая строка, с исходным временем события |
| Листание | бот, веб | `‹ Раньше` / `Позже ›`, правит то же сообщение / ту же таблицу |
| Сводная полоса | веб | на каждой странице; значения обновляются [ASSUMPTION: опрос раз в 5–10 с] |
| Плашка тревоги | веб | над содержимым любой страницы, пока тревога активна; узел с `role="alert"` вставляется один раз при появлении события; дальше меняется только строка контекста в `aria-live="polite"`; без кнопок: «не подтверждено» или «✅ Принято: <кто>, ЧЧ:ММ» |
| Таблетка статуса | веб | всегда со словом; не кликабельна |
| Таблица | веб | сортировка по столбцу; на < 560px — карточки; действия в строке ≥ 44px |
| Строка неисправности | веб | на сводке и в разделе; ведёт к каналу/узлу; исчезает при восстановлении |
| Плашка предупреждения | веб | висит, пока действует состояние; показывает срок и обратный отсчёт |
| Счётчик «новое» | веб | в меню у «Датчики» и «Конфликты»; исчезает, когда разобрано |
| История uplink | веб | подсказка по отрезку — время разрыва; число разрывов текстом |
| Форма канала/правила | веб | явное «Сохранить»; проверка при сохранении; ошибка у поля (warn + ⚠ + текст, `aria-describedby`) |
| Редактор `when` | веб | счётчик `n/256`; при сохранении ошибка с позицией («позиция 34: ожидалось `)`») или «Слишком глубокая вложенность: больше 8 уровней.» |
| Статус репликации | веб | «Сохранено на этом узле» → «На всех узлах» (≤ 1 мин); узел не на связи — «коридор не на связи — применится при возврате» |
| Поле секрета | веб | только запись; «задан · изменён …»; «Заменить»; рядом «хранится только на этом узле» и «задан на узлах: …» |
| Выбор срока | веб | выключение тревог канала: по умолчанию 2 ч, шаг 30 мин [ASSUMPTION], максимум 12 ч; «до ЧЧ:ММ» пересчитывается |
| Выбор при конфликте | веб | две карточки значений с узлом и временем, «Оставить это»; выбор — новая запись |
| Отличия импорта | веб | список «ключ: было → станет», итог «изменится N»; «Применить» через окно подтверждения |
| Мастер | веб, ввод | «Шаг N из M», одно действие на экран, «‹ Назад»; счётчик окна виден всегда |
| Пакет ключей | веб | «Скопировать ключи» кладёт в буфер пакет, зашифрованный кодом с наклейки нового узла; сам пакет не показывается; «Скопировано» на 3 с |
| Счётчик окна ввода | ввод | обратный отсчёт; по истечении — «Окно ввода закрыто. Нажмите кнопку ввода на узле.» |

## State Patterns

| Состояние | Поверхность | Отображение |
|---|---|---|
| Всё спокойно | меню бота, сводка | `🟢 Всё спокойно`; в вебе нет плашки тревоги |
| Активная тревога | бот, веб | см. «Тревога и её жизнь»; в вебе — `alarm-banner` на всех страницах, «не подтверждено» |
| Принято, тревога длится | бот, веб | «✅ Принято: <кто>, ЧЧ:ММ»; напоминаний нет; плашка остаётся, без свечения [ASSUMPTION] |
| Сообщение пролежало в очереди | бот | `⏳ с опозданием · событие в 03:12` |
| Узел пропал | бот «Статус», веб | «пропал N мин назад», цвет fault; событие «узел пропал» |
| Канал неисправен | бот «Датчики», веб | `обрыв` / `КЗ` / `молчит N мин` / `неисправен`, цвет fault |
| Числовой канал у порога | бот «Датчики», веб | 🟡 рядом со значком типа / `status-pill` «порог» |
| Новый канал без имени | веб | «Новые каналы» сверху «Датчиков», счётчик в меню |
| Тревоги канала выключены | бот, веб | `warn-banner` «до ЧЧ:ММ, кем», отсчёт; включаются сами |
| Тишина | меню бота, сводка | `🔇 общая тишина до ЧЧ:ММ`; `🔕 моя тишина до ЧЧ:ММ` — только в своём меню |
| Неподписанный чат | бот | «Чтобы получать тревоги: /subscribe PIN» |
| Лимит подписчиков | бот | «Список подписчиков заполнен — обратитесь к владельцу.» |
| Пусто | веб | одна строка и действие: «Подписчиков пока нет — поделитесь PIN.»; «Правил пока нет — [Создать правило]»; «Зон пока нет — [Добавить зону]»; «Событий пока не было.»; «Новых каналов нет.» (блок скрыт) |
| Первая загрузка | веб | каркас страницы сразу, значения «…» до ответа узла; без спиннеров во весь экран |
| Неверный логин | веб, вход | «Неверный логин или пароль.» у формы |
| Сессия истекла | веб | переход на вход с «Сессия истекла, войдите снова»; несохранённая форма теряется с предупреждением до перехода |
| Узел пропал посреди правки | веб | «Не сохранено: узел не отвечает. Откройте другой узел.» + адреса узлов |
| Репликация ждёт | веб | `warn-banner` «Сохранено на этом узле; «коридор» не на связи — применится при возврате» |
| Веб-узел недоступен | веб | браузер не открывает; в «Узлах» — адреса всех узлов, чтобы открыть другой |
| Запрос не из локальной сети | веб | соединение отклоняется, страниц нет |
| Предупреждение о сертификате | веб, первый вход | объяснение и отпечаток — на финальном экране ввода S3 и в инструкции к корневому сертификату; страница входа только напоминает «если браузер предупреждал — см. Доступы → Сертификат» |
| Конфликт правок | веб | счётчик в меню и полосе; в разделе — выбор значения |
| Правило незнакомого шаблона (N−1) | веб «Правила» | «не исполняется на узле X» |
| MQTT недоступен | веб «MQTT», полоса | «нет связи с брокером с ЧЧ:ММ», заполнение буфера; «Telegram и Pushover работают как обычно» |
| OTA узла | веб «Обновления» | проверка подписи → перезагрузка → вход в сеть → готово / откат; другим — «Ждёт: обновляется <узел>» |
| Неподписанный образ | веб «Обновления» | «Образ отклонён: подпись не подтверждена.» |
| OTA коллекторов | веб «Обновления» | таблица коллекторов: версия, «в очереди» / «передаётся N%» / «готово» / «откат»; события доставляются, передача ограничена |
| Окно ввода закрыто | ввод | «Окно ввода закрыто. Нажмите кнопку ввода на узле.» |
| Bluetooth выключен / нет разрешения | «Добавить коллектор» | «Включите Bluetooth и разрешите доступ браузеру.» + «Повторить» |
| Коллектор не найден | «Добавить коллектор» | «Коллектор не найден. Проверьте, что окно ввода открыто и телефон рядом.» + «Искать снова» |
| Нет Web Bluetooth | «Добавить коллектор» | Safari: «Откройте эту страницу в Bluefy.»; самоподписанная страница: запасной путь (Flow 3) |
| Captive-страница не открылась | ввод S3 | на наклейке и в инструкции — адрес страницы [ASSUMPTION: 192.168.4.1] |
| Неверный пароль WiFi | ввод S3 | «Не удалось подключиться к «<сеть>». Проверьте пароль.» — остаётся на шаге WiFi |
| Пакет ключей не подошёл | ввод S3 | «Пакет ключей не подошёл. Скопируйте его заново в вебе работающего узла.» |

## Interaction Primitives

- **Бот:** кнопки вместо набора команд; команды `/…` — синонимы. Ввод текста — только `/subscribe <PIN>`.
- **Веб:** клик, форма, явное «Сохранить». Автосохранения нет — правка реплицируется на всю сеть и должна быть осознанной.
- **Опасное — всегда с подтверждением**, в котором написано последствие.
- **Числа** вводятся с единицей рядом с полем и диапазоном в подсказке.
- **Буфер обмена** — только для пакета ключей, и только зашифрованного.
- **Запрещено:** менять правила или конфиг из Telegram (ответ отсылает к вебу); выключать тревоги канала из Telegram; подтверждать тревогу из веба; бессрочное выключение критичного; звуки и автоплей в вебе; перетаскивание как единственный способ правки графа зон; показывать секреты.

## Ввод узла

**Логический узел (S3).** Узел не введён или нажата кнопка ввода → поднимает свою WiFi-точку на время окна. Телефон подключается, открывается captive-страница (любой браузер). Шаги: (1) код с наклейки; (2) **«Создать новую сеть»** (первый узел — ключи генерируются) или **«Присоединиться»** (вставить пакет ключей из «Добавить большой узел»); (3) WiFi из списка + пароль; (4) токен Telegram, `OWNER_CHAT_ID`, ключ группы Pushover; (5) логин и пароль веба; (6) необязательно MQTT-логин, имя и зона; (7) «Готово. Узел перезагружается и войдёт в сеть. Веб: https://… Браузер предупредит о сертификате — отпечаток: `AB:12:…`; чтобы предупреждения не было, установите корневой сертификат из «Доступов».» После ввода точка выключается.

**Коллектор (H2).** Из веба работающего узла: Узлы → «Добавить коллектор» → «Нажмите кнопку ввода на коллекторе» + счётчик окна → `[Найти коллектор]` → системный выбор устройства → сверка EUI с наклейкой → код с наклейки, необязательно имя и зона → «Коллектор в сети · ключи переданы» → список его каналов «без имени» со ссылкой «Назвать каналы в «Датчиках»». Ключи сети передаются автоматически. На iPhone — в Bluefy; в Safari — «Откройте эту страницу в Bluefy.»

**Запасной путь** (Web Bluetooth недоступен на странице с сертификатом узла): статическая страница ввода с доверенного HTTPS-адреса; ключи — «Скопировать ключи» в вебе (пакет, зашифрованный кодом с наклейки коллектора) и вставка на этой странице.

Правила всех страниц ввода: мастер ≤ 480px, одно действие на экран, счётчик окна виден всегда; ничего, кроме секретов и активации. Повторный ввод — для смены секретов и владельца.

**Корневой сертификат**: «Доступы» → «Сертификат» → «Скачать корневой сертификат» и объяснение («Браузер предупреждает, потому что сертификат выпустила ваша система, а не публичный центр. Установите его один раз на каждый телефон.»). iPhone: открыть файл → Настройки → «Профиль загружен» → Установить; затем Основные → Об этом устройстве → Доверие сертификатам → включить. Android: Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС.

## Accessibility Floor

- Контраст текста ≥ 4,5:1 на всех парах — таблица в `DESIGN.md` §Colors; текст на `{colors.critical}` — только `{colors.on-critical}`; кнопка опасного действия залита красным.
- Границы полей и кольцо фокуса ≥ 3:1 к фону.
- Состояние никогда не передаётся только цветом или только эмодзи: всегда есть слово. Ошибка поля — цвет warn + ⚠ + текст.
- Кнопки бота — эмодзи + слово: экранные чтецы читают название эмодзи, слово даёт смысл.
- Веб: всё с клавиатуры, видимое кольцо `{colors.focus}`, порядок фокуса = порядок чтения; `lang="ru"`.
- Цели касания ≥ `{spacing.touch-min}` (44px) на ширине телефона, включая вкладки меню, листание и действия в строках.
- Ошибка поля связана с полем (`aria-describedby`) и объясняет, как исправить.
- Плашка тревоги объявляется один раз (`role="alert"`); обновления контекста — `aria-live="polite"`; при `prefers-reduced-motion` — статичная рамка `{colors.critical-edge}` без свечения.
- Масштабирование страницы до 200% без потери функций.

## Responsive & Platform

| Ширина | Веб |
|---|---|
| ≥ 1024px | боковое меню, таблицы полностью |
| 560–1023px | боковое меню уже, таблицы без второстепенных столбцов |
| < 560px | меню — ряд вкладок сверху; формы в одну колонку; таблицы — карточки; поля 16px |

Платформы: веб — современные мобильные и настольные браузеры в локальной сети; «Добавить коллектор» — Chrome на Android и настольный Chrome, Bluefy на iPhone; captive-страница — любой браузер. Бот — любой клиент Telegram; разметка только `<b>`, `<i>`, `<code>`, пользовательские имена экранируются.

## Inspiration & Anti-patterns

- **Взято из Grafana / залов мониторинга:** тёмный пульт, полоса статистики, таблетки статуса, моноширинные цифры.
- **Взято из 1.x:** меню правит само себя; уведомления о перезагрузке с причиной и лимитом; ежедневный «жив», чтобы тишина что-то значила.
- **Отвергнуто — копии меню в чате (1.x):** засоряют чат и прячут тревоги.
- **Отвергнуто — «бот в сети» при каждом старте (1.x):** в цикле перезагрузок стал потоком сообщений.
- **Отвергнуто — веб как панель наблюдения:** графики и живые дашборды — задача MQTT/Home Assistant.
- **Отвергнуто — одно «беззвучно» для всего:** критичное всегда звенит; 🔕 и 🔇 — разные вещи.

## Key Flows

### Flow 1 — Ночной дым (член семьи, 03:12, телефон в беззвучном)

1. Дымовой контакт в гараже замыкается; система создаёт критичное событие.
2. Pushover `priority=2` на ключ группы пробивает беззвучный режим у всех членов семьи с приложением.
3. В Telegram приходит `🚨 🔥 ДЫМ · ГАРАЖ`: «Сработал в 03:12.», `🌡 гараж: 18,0 → 31,0 °C за 10 мин ↑`, `Соседние зоны: 🟢 коридор — норма · 🟢 подвал — норма`, «Не подтверждено.», `🏠 гараж · ведущий`, `[✅ Принято] [📋 Статус]`.
4. Жмёт `📋 Статус` — узлы на связи, сработал один датчик.
5. **Climax:** жмёт `✅ Принято` — у всех получателей сообщение показывает `✅ Принято: член семьи, 03:14. Повторы остановлены.`, Pushover замолкает везде; веб показывает то же на плашке.
6. Если бы никто не подтвердил — в 03:27 `🔁 🔥 ДЫМ всё ещё · ГАРАЖ — 15 мин с начала, не подтверждено`. Контакт разомкнулся — `✅ 🔥 Дым в гараже прекратился · 03:41`.

Отказ: ведущий пропал во время тревоги → ведомый досылает критичное (≤ 60 с, ≤ 1 дубль); запоздавшее сообщение несёт `⏳ с опозданием`.

### Flow 2 — Отпуск (член семьи с ролью оператора, вечер перед отъездом)

0. Заранее владелец в вебе → «Подписчики» включил ему роль оператора.
1. Открывает бота → `‹ Меню` → `🛡 Режим`.
2. Видит текущий «Дома», жмёт «Уехал».
3. Экран: «Включить режим «Уехал»? Включатся правила движения. Критичные тревоги это не меняет.» → `✅ Подтвердить`.
4. **Climax:** всем подписчикам приходит `🛡 Режим «Уехал» включён — член семьи, 18:40`; меню показывает новый режим.
5. Каждое утро в 09:00 всем подписчикам приходит `📊` отчёт: узлы на связи, ведущий, события за сутки.

Отказ: подписчик без роли не видит `🛡 Режим`; `/mode` от него → «Смена режима доступна владельцу и операторам.»; подтверждение опоздало → «Время подтверждения вышло, повторите.»

### Flow 3 — Новый коллектор (владелец, подвал, телефон в руке)

1. Открывает веб любого логического узла → «Узлы» → «Добавить коллектор».
2. Шаг 1: подключает питание коллектора, нажимает на нём кнопку ввода; на странице пошёл счётчик окна → `[Найти коллектор]`, выбирает устройство.
3. Шаг 2: сверяет EUI с наклейкой → «Далее».
4. Шаг 3: код с наклейки, при желании имя и зона → «Подключить»; ключи сети передаются автоматически.
5. Шаг 4: «✅ Коллектор подвал-1 в сети · ключи переданы», каналы «без имени» → «Назвать каналы в «Датчиках»».
6. В «Новых каналах»: имя «Температура», зона «Подвал», порог → «Сохранить» → «На всех узлах».
7. **Climax:** проверочное срабатывание приходит в Telegram с именем и зоной: `⚠️ 🌡 Температура · Подвал …`.

Отказ: окно закрылось → «Окно ввода закрыто. Нажмите кнопку ввода на узле.»; неверный код → «Код не подошёл, проверьте наклейку.»; Bluetooth выключен или коллектор не найден — см. State Patterns; браузер не даёт Web Bluetooth на странице с сертификатом узла → «Bluetooth недоступен на этой странице» + «Скопировать ключи» → статическая страница ввода с доверенного адреса → «Найти коллектор» → вставить ключи → код.

### Flow 4 — Просмотр (член семьи днём; владелец вечером)

1. Член семьи: `‹ Меню` → `📡 Датчики` → зона «Гараж»: контакты «норма · последний раз …», числовые «значение · сутки мин…макс».
2. `‹ Меню` → `📜 События`: активное сейчас и история, `‹ Раньше`.
3. **Climax:** в одном сообщении, правящем само себя, видно всю сеть — без веба и без засорения чата.
4. Владелец: `‹ Меню` → `📈 Статистика`: подписчики, перезагрузки с причинами, отказы за 7 дней.

Отказ: ведущего нет (сеть без связи) — бот молчит, кнопка остаётся с «часиками»; ответ придёт, когда ведущий появится, или откройте веб. Список не помещается — сначала зоны кнопками.

### Flow 5 — Добавление большого узла (владелец, второй S3)

1. В вебе работающего узла → «Узлы» → «Добавить большой узел».
2. Вводит код с наклейки нового узла → «Скопировать ключи»: в буфере пакет, зашифрованный этим кодом; «Это секрет. Вставляйте только на страницу ввода узла.»
3. Включает новый S3, подключается к его WiFi-точке; открывается страница ввода.
4. Код с наклейки → «Присоединиться» → вставляет пакет.
5. WiFi и пароль → токен Telegram, `OWNER_CHAT_ID`, ключ группы Pushover → логин и пароль веба → имя «коридор».
6. **Climax:** «Готово. Узел перезагружается…» с адресом веба и отпечатком сертификата; через минуту в «Узлах» — «коридор · ведомый · на связи».

Отказ: пакет не подошёл (скопирован для другого кода или повреждён) → «Пакет ключей не подошёл. Скопируйте его заново в вебе работающего узла.»; неверный пароль WiFi → остаётся на шаге WiFi; окно закрылось → канонический текст; captive-страница не открылась → адрес с наклейки. Первый узел системы вместо шагов 1–2 и «Присоединиться» выбирает «Создать новую сеть».

### Flow 6 — Временное выключение тревог критичного канала (владелец, сломанный дымовик)

1. Дымовик в коридоре ложно звенит; владелец в вебе → «Датчики» → «Дым · коридор» → «Выключить тревоги».
2. Выбор срока: 2 ч по умолчанию, шаг 30 мин, максимум 12 ч; «до 05:12».
3. Окно подтверждения: «Тревоги канала «Дым · коридор» не придут до 05:12. Все подписчики получат оповещение.» → `Выключить тревоги`.
4. **Climax:** всем подписчикам — `⚠️ 🔥 Тревоги канала «Дым · коридор» выключены до 05:12 — владелец`; в вебе `warn-banner` с обратным отсчётом, в боте в «Датчиках» — `⚠️ тревоги выключены до 05:12`.
5. В 05:12 тревоги включаются сами; всем — `✅ 🔥 Тревоги канала «Дым · коридор» включены снова`.

Отказ: срок больше 12 ч → «Не больше 12 ч.» у поля; попытка из Telegram → «Правила меняются только в локальном вебе.»; узел пропал до сохранения → «Не сохранено: узел не отвечает. Откройте другой узел.»

### Flow 7 — Первая подписка (член семьи)

1. Владелец сообщает PIN; член семьи находит бота, жмёт «Старт».
2. Бот: «Чтобы получать тревоги: /subscribe PIN».
3. Отправляет `/subscribe 4821`.
4. **Climax:** «Вы подписаны. Тревоги придут сюда.» + главное меню подписчика; в вебе владельца — новая строка в «Подписчиках».

Отказ: неверный PIN → «Неверный PIN.»; список заполнен → «Список подписчиков заполнен — обратитесь к владельцу.»; любая другая команда до подписки → приглашение из шага 2.

### Flow 8 — Правило с условием (владелец, коротко)

1. «Правила» → «Создать» → шаблон «Состояние / порог», параметры, набор, важность, адресаты.
2. В `when`: `mode != "дома" and time in 22:00..07:00` (счётчик `n/256`).
3. «Сохранить» → «Сохранено на этом узле» → «На всех узлах».

Отказ: ошибка синтаксиса → подчёркивание и «позиция 34: ожидалось `)`»; длиннее 256 или глубже 8 → отказ с причиной; правило не выключается бессрочно, если это базовое правило критичного канала — ведёт в выбор срока Flow 6.

### Flow 9 — Обновление узла (владелец, коротко)

1. «Обновления» → выбрать файл образа для этого узла → «Загрузить».
2. Этапы: проверка подписи → перезагрузка → вход в сеть → **готово**.

Отказ: неподписанный образ → «Образ отклонён: подпись не подтверждена.»; не вошёл в сеть за время проверки → «Откат на версию 2.0.1»; обновляется другой узел → «Ждёт: обновляется <узел>».

## Вход и пакеты ключей

- Вход в веб: после 5 неверных попыток — пауза 5 мин, попытка пишется в журнал узла; текст «Слишком много попыток. Повторите через 5 мин.».
- Пакет ключей для нового узла — одноразовый, действует 30 мин; просроченный или использованный → «Пакет недействителен. Скопируйте новый в «Узлы» → «Добавить большой узел».».

## Открытые вопросы

- **Web Bluetooth на странице с самоподписанным сертификатом** (Chrome Android, Bluefy iOS) — проверить на стенде; при отказе — запасной путь Flow 3.
- **Формат машинной части аренды** и поведение при откреплении — архитектура 3.9.
- **Стартовые значения** (перенесены в `tunables.md`) (срок подтверждения в боте, шаг выбора срока, размер страницы событий, опрос сводной полосы) — перенести в `tunables.md`.
