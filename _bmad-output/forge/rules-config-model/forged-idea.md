# Forged idea: правила и конфигурация garageAlarms

**Статус:** HARDENED · 2026-09-29 · продолжает `../garage-device-network/forged-idea.md`

## Конфигурация — три уровня
- **H, прошивка:** манифест датчиков (драйвер, шина, пин, адрес), фиксированный набор драйверов, типы правил, базовые правила. Меняется только OTA.
- **S, мягкий конфиг:** имена, зоны, назначение, интервалы, пороги, экземпляры и наборы правил, режимы, граф зон, маршрутизация уведомлений. FRAM, версия на ключ (LWW), gossip.
- **R, рантайм:** значения, здоровье, last-seen. RAM + gossip.

## Датчики
- Логические узлы тоже могут иметь датчики; коллекторы — только датчики.
- **Канал** — единица модели: устройство → N каналов `binary | numeric | counter | enum` + единица, диапазон, здоровье.
- Самоописание в gossip: описание `{node, channel, kind, name, zone, purpose, criticality, unit, cfg_ver}` (по смене версии) + состояние `{state, value, health, ts, seq}` (по изменению и как heartbeat). Обмен сводками версий (anti-entropy).
- **Автообнаружение** на шинах для захардкоженного набора драйверов; найденный канал появляется в вебе без имени.
- Черновик набора: 1-Wire DS18B20 (выносные); I2C в корпусе — SHT4x/BME280, INA219 (питание), ADS1115 (шлейфы с EOL); GPIO — сухой контакт, импульсы. RS-485 — открыто.

## Правила
- Правило = **шаблон** (код) + экземпляр `{id, type, enabled, params, set, severity, notify, ver}` + необязательный **`when`** на ограниченном языке (и/или/не, сравнения, режим, время, состояние; без циклов/переменных).
- Шаблоны: порог · скорость изменения · здоровье · совпадение в окне · цепочка · трасса по графу зон · агрегация · действие/команда (опрос сейчас, burst-интервал с TTL) · режим/расписание (включает наборы).
- Производные события — детерминированный ID `rule_id + окно`.
- Команды — с ID и TTL; временные изменения откатываются сами.

## Управление и каналы
- Полная правка правил/конфига — **только локальный веб** (удалённо — через VPN).
- Telegram — урезанный набор: статус, отчёты, подтверждение, некритичное.
- Критичные правила — выключаются только временно (макс. N ч), каждое выключение — событие всем.
- **Второй канал = канал тревоги:** Pushover emergency (повтор до подтверждения, receipt); LTE/SMS позже. Подтверждение в любом канале гасит повторы везде.

## Лидерство (уточнение)
- Считают все логические узлы, **отправляет лидер**; ведомый держит копию.
- Лидер = живой узел с наименьшим ID **среди имеющих связь наружу** (`uplink` в heartbeat).
- Страховка: нет `delivered` за T (~45 с) → ведомый шлёт **критичное** сам.
- Telegram/Pushover не дедуплицируют — дедуп наш; 409 ограничивает split-brain одним циклом.

## Отвергнуто
- Мягкая привязка пин+драйвер из веба — не работает для не-бинарных датчиков.
- Полноценный язык правил (Lua) — шаблоны + `when` достаточно.
- Discord/Slack/Viber/WhatsApp/Signal как канал с ESP32.

## Открыто для архитектуры
- I2C только внутри корпуса; выносные — 1-Wire/RS-485. Одинаковые I2C-адреса → chip-id, мультиплексор.
- Pushover: возможны 2 экстренные тревоги при переключении — отмена по receipt.
- Значения T, N, интервалов gossip; окончательный набор драйверов.
