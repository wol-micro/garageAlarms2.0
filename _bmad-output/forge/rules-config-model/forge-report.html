Правила и конфигурация

Forge-сессия №2 · 29.09.2026 · продолжение «Децентрализованная сеть garageAlarms»

Главные находки

Считают все, отправляет лидер — и лидер тот, кто может говорить наружу. Лидерство идёт к узлу с наименьшим ID среди имеющих uplink, а критичное событие без отметки «delivered» за ~45 с ведомый шлёт сам.

Канал, а не датчик. Устройство даёт типизированные каналы; правила работают с каналами; стандартные шинные датчики находятся автоматически.

Три уровня конфигурации

УровеньЧтоКак меняется

Зафиксированные решения

  • Узел в gossip описывает свои каналы: имя, назначение, зона, тип, состояние, здоровье.
  • Привязка к железу — только прошивкой; автообнаружение на шинах для захардкоженных драйверов.
  • Правило = шаблон (9 типов) + экземпляр + необязательное условие when.
  • Производные события с детерминированным ID; команды с ID и TTL.
  • Полная правка — только локальный веб; Telegram урезан.
  • Критичные правила выключаются только временно, с оповещением всех.
  • Второй канал — канал тревоги: Pushover emergency, позже LTE/SMS.
  • Лидер = наименьший ID среди узлов с uplink; страховочная отправка критичного.

Отвергнуто

  • Мягкая привязка пин+драйвер из веба — не для I2C, 1-Wire, импульсных датчиков.
  • Полноценный язык правил (Lua) — хватает шаблонов и when.
  • Discord / Slack / Viber / WhatsApp / Signal — требуют публичного вебхука или не имеют API.
  • «Telegram/Pushover сами уберут дубли» — не убирают, дедуп наш.

Слабые места, пережившие проверку

  • I2C не для длинных кабелей — выносные датчики через 1-Wire или RS-485.
  • Одинаковые I2C-адреса у разных чипов — читать chip-id; больше двух одинаковых — мультиплексор.
  • Pushover без дедупа — возможны 2 экстренные тревоги при переключении, отмена по receipt.
  • Pushover идёт через тот же роутер — без LTE интернет остаётся единой точкой отказа.
