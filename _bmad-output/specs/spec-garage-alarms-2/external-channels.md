# Внешние каналы

В Telegram и Pushover отправляет `LEADER` (AD-10); критичное страхуют `FOLLOWER` и `YIELDED` (AD-10, AD-11); MQTT — MQTT-узел (AD-24).

## Telegram
| Команда | Кто | Действие |
| --- | --- | --- |
| `/subscribe <PIN>` | любой | подписка |
| `/unsubscribe` | подписчик (не владелец) | отписка |
| `/status` | подписчик | состояние, лидер, узлы, каналы |
| «Датчики», «События» | подписчик | состояние по зонам, последнее срабатывание, суточная статистика; история событий |
| «🔕 Моя тишина» | подписчик | некритичное без звука 1/4/8 ч, критичное всегда со звуком |
| `/test` | подписчик | тестовое сообщение |
| отчёты | подписчик | сводки событий |
| «Принято» | подписчик | `ack` тревоги |
| `/mute N` / `/unmute` («🔇 Общая тишина») | владелец | тишина некритичного для всех |
| «Статистика» | владелец | подписчики, перезагрузки, отказы за 7 дней |
| `/mode <режим>` | владелец и операторы, с подтверждением | смена режима (наборы правил); рассылается всем; критичное не затрагивает |
| `/leader <узел>` | владелец, с подтверждением | ручной лидер |
| `/reboot` | владелец, с подтверждением | перезагрузка узла |
| «Выходы» | владелец и операторы | вкл / выкл / авто для выходов с флагом `bot_control`; отказ с причиной, если выход держит защита |

Каждое сообщение подписано узлом и статусом (`🏠 гараж · ведущий`). Закреплённое сообщение в чате владельца — аренда лидера. Уведомления о перезагрузке — только владельцу, с причиной сброса, ≤ 1 за 15 мин. Ежедневный отчёт «жив» — всем подписчикам. Пауза между отправками.

Роли: **владелец** (всё), **оператор** (назначается в вебе: `/mode`, «Выходы»), **подписчик** (статус, отчёты, тест, «Принято»). Отправитель определяется по `from.id`, который подтверждает сервер Telegram.

## Pushover
Только критичные события, на ключ группы Pushover (вся семья): `priority=2` (retry ≥ 30 с, expire ≤ 3 ч), `tag = event_id`; receipt опрашивается не чаще раза в `GA_PUSHOVER_RECEIPT_POLL`; лишние копии — `cancel_by_tag`; подтверждение по receipt → `ack`.

## MQTT (AD-24)
Публикует MQTT-узел, JSON с `event_id`; Client ID — `ga2-<EUI-64>`. Темы: `<prefix>/<node>/<channel>/state` (QoS 1, retain), `<prefix>/<node>/health` (QoS 1, retain), `<prefix>/events` (QoS 1), `<prefix>/<node>/<channel>/result` (QoS 1, отказ команды с причиной). Команды — только выходам с флагом `mqtt_control`: `<prefix>/<node>/<channel>/set` (QoS 1), JSON `{value, id, ts, until?}` — `id` (строка, своя у каждой команды) и `ts` (Unix-время в секундах) обязательны, без них команда отклоняется с причиной в `result`; повтор по `id` в пределах `GA_CMD_MAX_AGE` отсекается точно и сообщается в `result`. Пример для Home Assistant (`mqtt.switch`): `command_template: '{"value": "{{ value }}", "id": "{{ now().timestamp() }}", "ts": {{ now().timestamp() }}}'` — обычные `payload_on`/`payload_off` не годятся, у них нет уникальных `id` и `ts`; retained, старше `GA_CMD_MAX_AGE`, из будущего (дальше `GA_TS_FUTURE_MAX`) и для выхода без `mqtt_control` отбрасываются; причина любой отброшенной или отклонённой команды публикуется в `result`. Отдельный ограниченный буфер; не задерживает основную очередь. Адрес, порт, TLS, префикс — мягкий конфиг; логин/пароль — на каждом узле.

## Ввод узла (SoftAP и Bluetooth)
| Передаётся | Логический (S3) | Коллектор (H2) |
| --- | --- | --- |
| Роль, ключ Zigbee-сети | да | да |
| Ключ HMAC сети с `kid` | да | — |
| Свой ключ коллектора K_c на каждый `kid` (выведен из ключа сети, AD-5) | — | да |
| WiFi, токен Telegram, `OWNER_CHAT_ID`, ключ Pushover, логин и пароль веба | да | — |
| Логин/пароль MQTT | необязательно | — |
| Имя и зона | необязательно | необязательно |

Логический узел (S3) вводится через свою WiFi-точку (страница в любом браузере): «Создать новую сеть» или «Присоединиться» с пакетом ключей из веба работающего узла. Коллектор (H2) — из веба работающей системы «Добавить коллектор» по Web Bluetooth, его ключи K_c и ключ Zigbee-сети передаются автоматически (ключ сети HMAC — никогда, AD-5). Не даёт управления, правил, режимов, подписчиков. Окно — после включения или по кнопке, ограничено по времени; Security 2 с кодом подтверждения (PoP) на наклейке; только до запуска Zigbee; после ввода выключается. Повторный ввод — для смены секретов и владельца.

## Внешний пульс (AD-30)

Узел, выбранный лидером по AD-9 (и в `YIELDED`, но не в `ISOLATED`), раз в `GA_PULSE_PERIOD` делает GET на адрес пульса из мягкого конфига (сервис «мёртвой руки», совместимый с healthchecks.io). Пинг не отправляется, если единица доставки критичного ждёт дольше `GA_PULSE_STALL`. Если пинги прекратились, сервис сам оповещает владельца — так видно полный отказ: нет питания, интернета или всех узлов. Срок ожидания задаётся на стороне сервиса (≥ 3 периодов).
