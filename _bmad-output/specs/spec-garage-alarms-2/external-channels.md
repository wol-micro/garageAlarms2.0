# Внешние каналы

Отправляет только `LEADER` (AD-10); `FOLLOWER` — страховка критичного (AD-11).

## Telegram
| Команда | Кто | Действие |
| --- | --- | --- |
| `/subscribe <PIN>` | любой | подписка |
| `/unsubscribe` | подписчик (не владелец) | отписка |
| `/status` | подписчик | состояние, лидер, узлы, каналы |
| «Датчики», «События» | подписчик | состояние по зонам, последнее срабатывание, суточная статистика; история событий |
| «🔕 Моя тишина» | подписчик | некритичное без звука 1/4/8 ч, критичное всегда со звуком |
| `/test` | подписчик | тестовое сообщение |
| отчёты | подписчик | сводки событий |
| «Принято» | подписчик | `ack` тревоги |
| `/mute N` / `/unmute` («🔇 Общая тишина») | владелец | тишина некритичного для всех |
| «Статистика» | владелец | подписчики, перезагрузки, отказы за 7 дней |
| `/mode <режим>` | владелец и операторы, с подтверждением | смена режима (наборы правил); рассылается всем; критичное не затрагивает |
| `/leader <узел>` | владелец, с подтверждением | ручной лидер |
| `/reboot` | владелец, с подтверждением | перезагрузка узла |
| «Выходы» | владелец и операторы | вкл / выкл / авто для выходов с флагом `bot_control`; отказ с причиной, если выход держит защита |

Каждое сообщение подписано узлом и статусом (`🏠 гараж · ведущий`). Закреплённое сообщение в чате владельца — аренда лидера. Уведомления о перезагрузке — только владельцу, с причиной сброса, ≤ 1 за 15 мин. Ежедневный отчёт «жив» — всем подписчикам. Пауза между отправками.

Роли: **владелец** (всё), **оператор** (назначается в вебе: `/mode`), **подписчик** (статус, отчёты, тест, «Принято»). Отправитель определяется по `from.id`, который подтверждает сервер Telegram.

## Pushover
Только критичные события, на ключ группы Pushover (вся семья): `priority=2` (retry ≥ 30 с, expire ≤ 3 ч), `tag = event_id`; лишние копии — `cancel_by_tag`; подтверждение по receipt → `ack`.

## MQTT (AD-24)
Публикует MQTT-узел, QoS 1, JSON с `event_id`. Темы: `<prefix>/<node>/<channel>/state` (retained), `<prefix>/events`, `<prefix>/<node>/health`, `<prefix>/<node>/<channel>/result` (отказ команды с причиной). Команды — только выходам с флагом `mqtt_control`: `<prefix>/<node>/<channel>/set`, JSON `{value, until?, ts?}`; retained и старше `GA_CMD_MAX_AGE` отбрасываются. Отдельный ограниченный буфер; не задерживает основную очередь. Адрес, порт, TLS, префикс — мягкий конфиг; логин/пароль — на каждом узле.

## Bluetooth — только ввод узла
| Передаётся | Логический (S3) | Коллектор (H2) |
| --- | --- | --- |
| Роль, ключ Zigbee-сети, ключ HMAC с `kid` | да | да |
| WiFi, токен Telegram, `OWNER_CHAT_ID`, ключ Pushover, логин и пароль веба | да | — |
| Логин/пароль MQTT | необязательно | — |
| Имя и зона | необязательно | необязательно |

Логический узел (S3) вводится через свою WiFi-точку (страница в любом браузере): «Создать новую сеть» или «Присоединиться» с пакетом ключей из веба работающего узла. Коллектор (H2) — из веба работающей системы «Добавить коллектор» по Web Bluetooth, ключи передаются автоматически. Не даёт управления, правил, режимов, подписчиков. Окно — после включения или по кнопке, ограничено по времени; Security 2 с кодом подтверждения (PoP) на наклейке; только до запуска Zigbee; после ввода выключается. Повторный ввод — для смены секретов и владельца.
